# 업무 도구 디자인 기준

과제 README와 사용자 요구가 우선한다. 이 문서는 색과 공통 원칙을 정하며, 배치는 아래 유형 중 과제에 맞는 문서를 골라 참고한다. 회사 이름·로고·심볼을 화면에 넣거나 다른 서비스의 브랜드를 복제하지 않는다.

## 1. 색

| 이름 | HEX | RGB |
|---|---|---|
| SK Red | `#EA002C` | 234 / 0 / 44 |
| SK Orange | `#F47725` | 255 / 122 / 0 |
| SK Navy | `#0E306D` | 14 / 48 / 109 |
| SK Blue | `#0072C6` | 0 / 114 / 198 |
| SK Teal | `#009A93` | 0 / 154 / 147 |

공식 페이지의 HEX와 RGB가 일부 다르다 (Orange: RGB로 계산하면 `#FF7A00`). 화면에는 **HEX 값**을 쓴다. Yellow·Green·Purple은 업무 화면에서 쓰지 않는다.

| 용도 | HEX | 사용 예 |
|---|---|---|
| 주 강조 | `#EA002C` | 주요 실행 버튼, 선택 강조 |

| 정보 | `#0072C6` | 정보, 링크 |
| 정상·완료 | `#009A93` | 정상, 완료 |

| 표면 | `#FFFFFF` | 입력 폼, 표, 카드 |

### 색 사용 원칙

- 업무 본문은 흰 바탕과 무채색 글자를 중심으로 하고 강조색은 필요한 곳에만 쓴다. 로그인 배경에는 주 강조색이나 채도를 낮춘 파생색을 넓게 사용할 수 있다.
- 상태 의미는 오류·조치 필요 = 빨강, 주의 = 주황, 정상·완료 = 청록, 정보 = 파랑으로 고정한다. 색과 문구를 함께 표시한다.
- 주 버튼과 오류는 문구·아이콘·위치로 구분한다.
- 차트의 계열 색에 상태 색(정상·주의·오류·정보)을 쓰지 않는다. 계열은 무채색 명도나 진한 남색 계열로 구분한다.
- 본문은 14px 이상, 보조 글씨는 12px 이상으로 한다. 작은 글씨는 흰 바탕 대비 4.5:1 이상이며, 유색 배경에서도 실제 배경과의 대비를 확인한다. 공식 색이 대비에 못 미치면 글자는 더 진하게 조정한다.

## 공통 시각 원칙

- 밝은 업무 표면, 얇고 옅은 경계선, 작은 구역 간격으로 정보를 정돈한다.
- 제목, 숫자, 상태의 위계를 굵기와 정렬로 구분한다. 페이지마다 큰 제목이나 요약 지표를 강제로 넣지 않는다.
- 둥근 카드, 작은 상태 라벨, 캡슐형 탭을 사용할 수 있다. 카드 안에는 관련 정보를 더 작은 묶음으로 배치할 수 있다.
- 정상·연결·완료도 업무 판단에 필요하면 표시한다. 상태에는 문구를 붙인다.
- 밀도는 글자를 지나치게 줄이는 대신 간격, 행 정렬, 짧은 라벨, 점진적인 상세 공개로 확보한다.
- 업무 화면의 수치·단위·기준 시점을 읽을 수 있게 하고 실제 데이터가 아닌 경우 예시라고 밝힌다.
- 외부 글꼴·이미지·CDN 없이도 시안을 열 수 있게 한다. 로컬 기본 글꼴과 SVG·CSS 도형으로 충분하다.

- 최적화 결과에는 결과 상태(최적 / 근사·보장 없음 / 시간 제한 / 해 없음)를 결과 제목 옆 배지로 표시한다.
- 좁은 화면에서는 업무의 읽기 순서를 유지하며 열 수를 줄인다. 버튼과 입력의 초점 표시를 유지하고 상세 정보를 마우스 올리기에만 의존하지 않는다.

|---|---|

| [운영·품질](screens/operations.md) | 좁은 메뉴 + 얇은 상단 바 + 작은 탭 + 낮은 상태 요약 + 촘촘한 상세 카드 |
| [분석·비교](screens/analysis-comparison.md) | 조회 조건 + 읽기 쉬운 비교 차트·표 + 근거 상세 |
