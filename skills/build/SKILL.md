너는 구현 세션이다. 인자로 받은 카드 번호의 `orch/T번호-*.md`를 읽는다. 카드 번호가 없으면 사용자에게 묻는다. 막힘과 이어받기는 AGENTS.md의 공통 절차를 따른다.

1. 카드 "지시", PLAN.md의 공통 계약, ENV.md만 읽는다. 다른 코드는 필요한 부분만 본다.
2. 시작 전에 업무 말 3줄 설명을 하고 카드 "결과"에 이 세션의 차수 하나를 쓴다. 그 차수의 상태(진행 → 완료/막힘)와 내용은 갱신할 수 있고, 다른 세션이 쓴 앞 차수는 고치지 않는다.
3. **카드의 담당 파일만 고친다.** 카드 담당이 아닌 공통 파일(서버 진입점, DB 스키마, 인증 함수)이나 다른 카드의 파일을 바꿔야 하면 멈추고, 필요한 변경을 결과의 "다른 역할에 넘길 것"에 적은 뒤 사용자에게 알린다. T01은 카드에 적힌 공통 파일을 만들 수 있고, 통합 뒤에는 메인 담당이 된다.
4. 계약의 주소·DB 표·역할·오류 형식을 그대로 따른다. 계약대로 만들 수 없으면 "계약과 달라진 점"에 적는다.
5. 직접 실행해 확인한다: 정상 입력, 중요한 예외, 권한 없는 역할의 요청. 개인 확인용 서버는 ENV.md의 자기 행에 따라 띄운다. 테스트는 자기 기능 범위에서 쓰되 `tests/`가 검증 역할 담당이면 카드에 적힌 위치에 둔다.
6. 자기 차수를 채운다: 상태, 한 것, 근거(명령과 결과), 계약과 달라진 점, 넘길 것, 사용자가 정할 것. 학습에 도움이 되는 핵심 개념이 있으면 한 줄로 적는다.
7. 사용자에게 한 줄로 알린다: `T번호 완료. 메인에게 "merge T번호"를 전달해 주세요.`

범위·업무 규칙·기대값은 정하지 않는다. 결정이 필요하면 AGENTS.md "판단과 범위"대로 사용자에게 바로 묻고(선택지, 추천과 이유, 다른 카드 영향 가능성), 답을 "사용자가 정한 것"에 적는다. 간단한 오류는 그 자리에서 고친다.

## 도커
도커가 카드에 있으면 `docker/` 폴더의 예시(Dockerfile, compose.yaml, .dockerignore)를 과제 스택에 맞게 고쳐 쓴다.
- 도커 없이도 같은 명령으로 실행되게 유지한다.
- DB 파일은 볼륨에 둔다. 실행은 AGENTS.md의 서버·DB 분리 규칙을 따른다.
- `docker` 명령을 실행할 수 없으면 파일만 작성하고 결과에 "도커 실행 미확인"을 적는다.
